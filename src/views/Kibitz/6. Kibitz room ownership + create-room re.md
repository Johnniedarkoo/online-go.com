# Kibitz room ownership + create-room redesign handoff

## Goal

Improve room ownership UI and permissions without adding a new permanent surface to the main room layout.

The room page should stay board-first and clean. Governance should move out of the always-visible action row and into a compact, progressive-disclosure UI.

At the same time:

* desktop create-room should stop using a second details popup
* desktop Observe-based selection should stop rendering the same goban twice
* the design should support future Curators cleanly

## Role model

### Owner

Can:

* change room name
* change room description
* change live game
* later appoint/unappoint Curators

### Curator

Can:

* change room description
* change live game

Cannot:

* change room name
* appoint/unappoint others

### Viewer

Can:

* watch, chat, use normal room features
* see who manages the room

Cannot:

* open management actions

## Core design decision

Do not add a new visible ownership block.

Instead:

* use a small **gear** in the existing room title strip
* open a **popover** from that gear
* move governance actions into that popover
* remove standalone **Change board** from the normal visible UI

This keeps the room page clean and avoids fighting the board geometry.

---

# 1. Main room UI changes

## Current problems in this snapshot

### `KibitzRoomStage.tsx`

The main board meta area currently shows:

* room title
* board subtitle
* player row
* action buttons including `Create variation` and `Change board`

This makes `Change board` feel like a routine board action, when it is really room governance.

### `KibitzRoomList.tsx`

The left rail also surfaces `Change board` in the general actions row.

That is too broad and reinforces the wrong model.

## New behavior

### Keep visible

In the existing room title strip:

* room title
* current game subtitle
* player row
* variation action if still desired

### Add

A small **gear button** in the room title area.

Visible only if current user can manage the room:

* Owner: yes
* Curator: yes
* Viewer: no

### Remove

Remove standalone `Change board` from:

* `KibitzRoomStage.tsx`
* `KibitzRoomList.tsx`

It should no longer appear as a normal top-level action.

## Why

This cleanly separates:

* **activity**: create variation
* **governance**: manage room

That distinction is missing in the current UI.

---

# 2. Gear popover behavior

The gear opens a compact anchored popover from the title strip.

This is the room management entry point.

## Popover menu structure

### Owner sees

* **Edit room details**
* **Change live game**
* later: **Manage curators**

### Curator sees

* **Edit room details**
* **Change live game**

### Viewer

No gear, so no popover.

## Notes

Do not make this a full admin dashboard.
Do not add a second visible row in the room UI.
The popover is the governance surface.

---

# 3. Edit room details flow

## Current problem

Desktop create-room currently sends room name and description into a second popup. That feels clumsy.

For existing rooms, the new design should also avoid nested modal complexity.

## New behavior

Selecting **Edit room details** from the gear should expand or replace the popover contents with a compact inline form.

Do not open a second modal.

## Fields by role

### Owner

Editable:

* room name
* room description

### Curator

Editable:

* room description

Room name should be visible as read-only or plain text, but not editable.

## Save model

Use:

* Save
* Cancel

No extra confirmation popup for metadata edits.

## Description visibility on main room

Keep description hidden on the main room page.

That is intentional. The room page stays clean.
Description remains editable in management UI and visible in the room list subtitle.

---

# 4. Change live game flow

## Entry point

Only available through the gear popover.

## Behavior

Choosing **Change live game** opens the large game-picker overlay.

Reason:
game selection is too large and complex for a popover.

## Permissions

* Owner: allowed
* Curator: allowed
* Viewer: unavailable

## Important change

Because `Change board` disappears from the always-visible UI, this becomes the only governance entry for live-game switching.

---

# 5. Desktop create-room redesign

## Current problem

`KibitzGamePickerOverlay.tsx` currently does this on desktop:

* left pane: Observe list
* right pane: selected-game preview
* then `Set room details`
* then second popup for name/description via `showRoomDetailsPopup`

This is unnecessary.

## New desktop create-room model

Keep the overlay, but flatten the flow.

### Left pane

Game source and selection:

* Ongoing / Observe
* Game ID / URL

### Right pane

Selected game summary plus room fields inline:

* selected game metadata
* existing room suggestion
* room name
* room description
* create button

## Remove

Delete `showRoomDetailsPopup` on desktop create-room flow.

There should be no second desktop popup for room details.

## Result

Desktop create-room becomes one coherent surface.

---

# 6. Duplicate goban fix

## Current problem

In `KibitzGamePickerOverlay.tsx`, the Observe list uses `initialMiniGoban={true}` and the selected game is also rendered again in the right pane.

That duplicates the same board and wastes space.

## New rule

### When source is Observe / ongoing

Do **not** render a second goban in the right pane.

The Observe list already provides board preview.

The right pane should show:

* metadata
* existing-room hint
* room fields or confirmation controls

### When source is Game ID / URL

Do render the right-pane goban preview.

Reason:
there is no left-side board preview in that mode.

## Implementation consequence

The selected-game card in `KibitzGamePickerOverlay.tsx` should support two desktop variants:

* `withBoardPreview`
* `metadataOnly`

Use `metadataOnly` for desktop ongoing-source mode.

---

# 7. Change-live-game overlay redesign

The same picker core is reused, but the right pane should differ by mode.

## Create room mode

Right pane shows:

* selected game summary
* existing room suggestion
* room name field
* room description field
* create action

## Change live game mode

Right pane shows:

* selected game summary
* confirmation/action area only

No room metadata fields.

This keeps the two flows related, but no longer identical.

---

# 8. Ownership visibility in presence list

This is the right place to expose managers publicly.

## Current state

`KibitzPresence.tsx` currently renders a simple presence roster.

## New behavior

Pin room managers to the top of the presence list.

### Order

* Owner first
* later Curators
* then the normal room roster

## Important rule

This should be role-based, not join-order-based.

Managers should stay pinned even if they are not part of the normal join-order roster behavior.

## Visual treatment

Keep it subtle:

* small owner marker/icon
* small curator marker later
* optional role label

Do not add a new outer panel.
This should be a pinned subsection at the top of the existing presence surface.

---

# 9. Future-proofing for Curators

Curators do not ship yet, but the UI should anticipate them.

## In the popover

Structure the management IA so a future People section fits naturally:

* Room details
* Live game
* later: People

## In presence

Design the top-pinned manager section so it already supports:

* one owner
* zero or more curators

Even if v1 only shows Owner now.

## Permissions

Do not hardwire management UI to a single boolean like `canChangeBoard`.
Use capability-style checks or a derived role model so Curator can slot in later cleanly.

# 10. Recommended code changes

## `KibitzRoomStage.tsx`

Change the main title/meta strip.

### Remove

* visible `Change board` button
* empty-state `Change board` button in primary board area

### Keep

* room title
* subtitle
* player row
* create variation action if still desired

### Add

* small gear button in title row
* popover state management hook/props
* owner/curator visibility logic

### Suggested prop changes

Instead of `onChangeBoard?: () => void`, move toward something like:

* `canManageRoom?: boolean`
* `onOpenRoomSettings?: () => void`

Or pass both for transition, but the rendered UI should use the gear path.

---

## `KibitzRoomList.tsx`

### Remove

* visible `Change board` action from the left-rail actions row

### Keep

* `Create room`

### Optional

Leave `Create variation` only if it still makes sense there, but it should not be mixed with governance.

---

## `KibitzGamePickerOverlay.tsx`

This is the biggest desktop flow change.

### Remove

* desktop `showRoomDetailsPopup`
* desktop `Set room details` button
* desktop room-details popup subtree

### Replace with

Inline desktop form in the right pane for create-room mode:

* room name
* room description
* create button

### Add conditional layout

When `sourceMode === "ongoing"` on desktop:

* suppress duplicate right-pane goban
* render metadata-only selection card

When `sourceMode === "game-id"`:

* keep board preview in right pane

### Keep mobile separate

Mobile can remain step-based.
The change here is primarily desktop.

---

## `KibitzPresence.tsx`

### Add

A pinned manager section above `presence-users`.

Suggested rendering order:

* owner row
* curator rows later
* separator if useful
* normal presence users

### Data requirement

The room object or derived view model needs enough data to identify:

* owner
* later curators

If not already present, add it to the room summary/details layer.

---

## `Kibitz.tsx`

This is where the page wiring lives.

### Update stage wiring

Replace `onChangeBoard={onOpenChangeBoard}` path with:

* gear/open-settings flow

### Update room list wiring

Stop passing `onChangeBoard` to `KibitzRoomList`.

### Add settings/popover state

You likely need page-level or stage-level state for:

* room settings popover open/closed
* selected management subview:

  * menu
  * edit details
  * change live game

# 11. Suggested component additions

To keep this tidy, I would introduce small focused components rather than bloating `KibitzRoomStage.tsx`.

## New components

* `KibitzRoomSettingsTrigger`
* `KibitzRoomSettingsPopover`
* `KibitzRoomDetailsForm`
* maybe `KibitzRoomManagers`

## Why

This keeps:

* stage layout code
* management popover code
* permission rendering
* form logic

from becoming tangled.

# 12. UX states to implement

## Main room states

### Viewer

* no gear
* no governance actions visible
* owner pinned in presence list

### Owner

* gear visible
* gear opens popover with room details + live game actions

### Future Curator

* gear visible
* room name not editable
* description and live game editable

---

## Gear popover states

### Menu state

* Edit room details
* Change live game

### Edit details state: Owner

* room name input
* room description textarea
* save/cancel

### Edit details state: Curator

* room name read-only
* room description editable
* save/cancel

### Change live game action

* closes popover
* opens game-picker overlay in change-board mode

---

## Desktop create-room states

### Ongoing source, nothing selected

* Observe list left
* right pane mostly empty/helpful placeholder
* inline room fields disabled or hidden

### Ongoing source, game selected

* no duplicate goban in right pane
* metadata only
* room fields visible
* create enabled when valid

### Game ID source, valid selection

* right-pane goban visible
* metadata + room fields visible

### Existing room found

* show join-existing-room suggestion inline in right pane
* still allow create-room

# 13. Non-goals

Out of scope for this pass:

* shipping Curator assignment UI
* adding a persistent room description block to the room page
* adding a new management section beneath the board
* exposing change-game as a normal visible top-level button again
* redesigning mobile ownership flow beyond what is needed for parity

---

# 14. Acceptance criteria

This redesign succeeds if:

* the main room page remains visually as clean as it is now
* there is no new permanent ownership block
* `Change board` disappears from always-visible desktop UI
* room governance is accessible through a small gear in the title strip
* desktop create-room no longer uses a second room-details popup
* desktop Observe selection no longer shows the same goban twice
* owner is publicly visible at the top of the presence list
* the permission structure already supports future Curator expansion cleanly

---

1. Remove visible `Change board` from `KibitzRoomStage.tsx` and `KibitzRoomList.tsx`
2. Add gear trigger to room title strip
3. Build room settings popover with menu + room details form
4. Flatten desktop create-room flow in `KibitzGamePickerOverlay.tsx`
5. Add metadata-only right-pane variant for ongoing-source desktop selection
6. Add pinned owner section to `KibitzPresence.tsx`
7. Refactor permission logic so Owner/Curator capabilities are easy to extend later
